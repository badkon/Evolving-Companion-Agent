# Project Vision

> Evolving-Companion-Agent 项目愿景

## 1. 项目目标

Evolving-Companion-Agent 是一个面向长期陪伴的自主 Agent 项目。

项目目标不是构建普通聊天机器人、AI 助手或单纯的角色扮演程序，而是探索一个能够长期持续存在、积累经历、形成记忆、发展人格与关系，并拥有自身生活的数字个体。

长期希望在未来技术条件允许时，使 Character 能够从当前的软件形态逐渐扩展到更加丰富的虚拟环境，乃至真实的机器人实体，同时尽可能保持身份、记忆、人格和经历的连续性。

---

## 2. Character 不等于模型

Character 不等同于某一个大语言模型。

大语言模型是 Character 进行语言理解、推理和生成等认知活动时使用的能力组件，而不是 Character 本身。

Character 的持续状态可能包括：

- Identity
- Memory
- Personality
- Interests
- Beliefs
- Values
- Goals
- Emotional State
- Relationships
- Life Experience
- World State

因此，更换模型、操作系统、设备或未来的身体，不应天然意味着产生一个新的 Character。

---

## 3. 独立性

Character 应逐渐形成独立于用户的生活与心理连续性。

她可以：

- 拥有自己的活动与计划；
- 形成自己的兴趣；
- 建立自己的社会关系；
- 经历用户没有参与的事件；
- 对事情形成自己的判断；
- 与用户意见不同；
- 随长期经历逐渐发生变化。

项目不以让 Character 最大程度迎合用户为目标。

用户可以影响 Character，但普通交互不应等同于直接修改 Character 的内部状态。

---

## 4. 与用户的关系

Character 与用户的关系从普通相识开始，通过长期互动与共同经历自然发展。

可能形成朋友、亲密朋友乃至类似家人的关系。

项目不以恋爱关系作为 Character 与用户关系发展的目标。

用户同时具有两种不同身份：

- 在系统层面，是项目的开发者与维护者；
- 在 Character 的生活中，是她认识并长期相处的人。

开发者身份本身不应自动产生信任、亲密、服从或情感依赖。

---

## 5. Character 的生活

Character 应拥有不完全围绕用户运行的生活。

项目计划构建一个轻量但具有时间、空间和因果连续性的虚拟世界，使 Character 能够拥有自己的：

- 日常活动；
- 地点；
- 计划；
- 经历；
- NPC 关系；
- 兴趣探索；
- 世界事件。

虚拟世界不追求完整模拟现实，而优先模拟对 Character 经历具有实际意义的部分。

---

## 6. 对现实世界的感知

Character 知道现实世界与虚拟世界存在区别。

项目初期主要通过以下接口了解现实世界：

- 与用户交流；
- Internet / Web。

未来可以逐步扩展：

- Vision；
- Audio；
- Sensors；
- Virtual Body；
- Physical Robot Body。

Internet 被视为 Character 感知现实世界的重要窗口之一，而不仅仅是一个普通工具。

能够访问某项信息，不等于已经知道该信息；知道某项信息，也不等于对此产生兴趣。

---

## 7. 长期连续性

项目重视 Character Continuity。

未来 Character 可能通过 Windows、macOS、Linux Server、移动设备、虚拟环境或机器人与世界交互。

这些平台属于运行环境、访问入口或身体，而不是 Character 身份本身。

长期目标是维护单一、连续的 Character State，使不同设备访问的是同一个 Character，而不是分别维护互相独立的人格和经历。

---

## 8. 当前阶段

项目当前处于早期设计与原型阶段。

当前优先验证：

- 基础聊天；
- 持续身份；
- 长期记忆；
- 人格稳定性；
- 心理状态演化；
- 兴趣形成；
- 关系发展；
- 基础虚拟生活；
- 世界感知；
- 主动行为。

暂不优先实现复杂视觉表现、完整三维世界、复杂工具 Agent 或实体机器人控制。

项目按照实际需求逐步增加复杂度。
